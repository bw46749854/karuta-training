# ADR-0002: 乱数

- ステータス: 承認待ち
- 日付: 2026-10-31

## 背景

出題の順番、配る札、札の向きは、ランダムに決める（[仕様 03](../spec/03-questions-and-dealing.md)）。設計方針は、`domain` が乱数を直接使わないこと、時刻と乱数をポートで受け取ること、乱数は種を指定できることを決めている（[設計方針](../design/principles.md) §2.1〜§2.3）。乱数の形と作り方は、まだ決めていなかった。

現行サンプルの使い方（コードで確認）：

- 乱数を使う所は7か所。出題順・配る札・配置暗記の出題順の5か所はシャッフル、札の向きの2か所は `Math.random() < 0.5`。
- シャッフルは5か所とも Fisher–Yates 法で、手順に偏りはない。`sort` に乱数を渡す、偏りのある書き方は使っていない。
- `Math.random` は種を指定できないので、同じ並びを再現できない。

## 決定

### 1. `domain` が受け取る乱数の形

- 「0 以上 n 未満の整数を1つ、どれも同じ確からしさで返す」関数を、引数として受け取る。
- `domain` は、整数の選び方だけを使う。シャッフルの各手順は「残り k 枚から1枚を選ぶ」、札の向きは「2つから1つを選ぶ」。
- `application` の `Random` ポート（設計方針 §2.2）が、この関数を提供する。

### 2. アプリで使う乱数の作り方

- 種を指定できる擬似乱数 xoshiro128\*\*（内部状態 128 ビット、32 ビットの値を出す。考案者がパブリックドメインで公開）を、自分で実装する。実行時の依存は増やさない。
- 32 ビットの値から 0 以上 n 未満の整数を作るときは、端の値を捨てて引き直す方法で、偏りをなくす。
- 置き場所は、`Random` ポートの実装として `packages/adapters-web`。ほかの公開先のアダプタを作るときに、共通の置き場所へ移すかを決める。

### 3. 種の決め方

- アプリの起動時に1回、ブラウザの暗号用の乱数（`crypto.getRandomValues`）から 128 ビットの種を作る。予想できない種になる。
- 種がすべて 0 のとき（xoshiro128\*\* が動かない状態。2⁻¹²⁸ の確からしさ）は、作り直す。

### 4. シャッフル

- Fisher–Yates 法。後ろから順に、まだ決まっていない札の中から1枚を選んで入れ替える。
- k 枚を選ぶときは、シャッフルした先頭の k 枚を取る。どの k 枚の組も、同じ確からしさで選ばれる。

### 5. 偏りがないことの確かめ方

| 確かめること | 方法 |
|---|---|
| シャッフルの手順 | 5枚までの札について、整数の乱数の取りうる値の組をすべて与える（5枚なら 5×4×3×2 = 120 通り）。どの並びもちょうど1回ずつ出ることを確かめる。統計ではなく全数で確かめる |
| 整数の作り方 | 捨てて引き直す境目の前後の値を与えて、正しく引き直すこと、どの整数も同じ数の値から作られることを確かめる |
| 擬似乱数 | 考案者の参照実装（C 言語）と、同じ種から同じ値が出ることを確かめる |
| 全体（任意） | 種を固定して3枚を何万回も並べ、6通りがほぼ同じ回数ずつ出ることを見る。種を固定するので、実行のたびに結果が変わることはない |

### 6. テストでの乱数

- 単体テスト：乱数の代わりに、選ぶ整数の並びをそのまま与える。
- E2E：アプリが読み込まれる前に、Playwright で `crypto.getRandomValues` を差し替えて種を固定する。テストのための仕組みを、アプリに入れない。

### 7. 札の向き

仕様 03 §4・§5 のとおり、札流しは1枚ごと、複数枚は問ごとに、ほかと関係なく半々で決める（サンプルと同じ）。次の向きを予想できないことを優先し、少ない枚数で片方の向きに偏ることは受け入れる（例：3枚がすべて同じ向きになる確からしさは 25%）。

## 却下した選択肢

| 選択肢 | 退けた理由 |
|---|---|
| `domain` が 0 以上 1 未満の小数を受け取る | `domain` で整数に直す処理が要り、偏りの扱いが散らばる。テストで狙った値を作りにくい |
| 乱数の状態を値で渡し、新しい状態を返してもらう | `domain` は完全な純粋関数になるが、呼び出しのたびに状態を受け渡すので書き方が重い。整数を返す関数を引数で受け取れば、テストでは決めた並びを与えられ、毎回同じ結果になる |
| `Math.random` | 種を指定できず、同じ並びを再現できない（設計方針 §2.2 に反する） |
| 乱数のライブラリ（pure-rand など） | 実績はあるが、実行時の依存が増える。必要な部分（擬似乱数と偏りのない整数化）は数十行で書け、参照実装との一致で確かめられる |
| 向きを、ちょうど半分ずつにする、または同じ向きの続く回数に上限を付ける | 偏りは減るが、終盤や上限に来たときに次の向きが分かる。ユーザーの決定で、予想できないことを優先した（2026-10-31） |

## 範囲と制約

### 標準でできること

- 種を決めれば、出題の順番・配る札・札の向きを、毎回同じに再現できる（テスト）。
- `domain` のテストは、選ぶ整数の並びを与えるだけで、すべての場合を決まった結果で試せる。

### 追加実装でできること（実施するかは別途判断）

- 種を記録して、報告された回の並びを再現する。新しい機能になるので、提案として別に扱う。

### 諦めること

- **すべての並びを出すこと**：内部状態が 128 ビットなので、作れる並びは最大で約 3×10³⁸ 通り。100枚の並べ方（約 9×10¹⁵⁷ 通り）のほとんどは出ない。実際に見分ける方法はなく、`Math.random`（Chrome と Firefox も内部状態 128 ビット）でも同じ。仕様 03 の「偏りがない」は、手順に偏りがないことを指す。
- **暗号に使える強さ**：xoshiro128\*\* は、予想されると困る用途（暗号）には使えない。練習の出題には要らない。

## この決定を見直す条件

- 重み付きの確率など、整数の選び方では表せない乱数が要るようになったとき（形を足す）。
- ほかの公開先で、`crypto.getRandomValues` が使えないとき（種の作り方を変える）。
- 種の記録と再現を機能として入れるとき（種を作る時機を、起動時から練習の回ごとに変えるかを決める）。
