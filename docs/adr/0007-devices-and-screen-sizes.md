# ADR-0007: 機器・画面の大きさ

- ステータス: 承認待ち
- 日付: 2026-11-01

## 背景

### 決まっていること

| 決まっていること | 出どころ |
|---|---|
| 公開先は Web（PWA）、iOS/iPadOS・Android（Capacitor）、PC・Steam（Steam Deck を含む） | ADR-0001 |
| すべての操作を、タッチ・マウス・キーボードでできる。コントローラーだけでもできるように設計する | ADR-0001、設計方針 §2.4 |
| アプリ版の起動時間の予算（コールド起動 1 秒以内など）は、公開するときに基準の端末で確かめる。基準の端末は、この ADR で決める | ADR-0001「起動時間の予算」 |
| E2E テストは、Chromium・WebKit・Firefox と、iPad 相当の画面で動かす | 設計方針 §4（今の設定は、デスクトップの 3 つと「iPad（第7世代）」縦 810×1080） |
| 画面に出すものは、目的で選ぶ。答える・結果を知る・進み具合を知る・次の操作を知る・今どの画面か | ADR-0006 |
| 盤面は 6 段×11 列（66 マス）。札の配置の初期値は各陣 25 マス | 取扱説明書 §6.3 |

### 現行サンプルの動き（2026-11-01 に Chromium で確かめた）

配置暗記の盤面は、画面の大きさに関わらず 842×642 の決まった大きさで、札は 76×106。

| 画面の大きさ | 盤面 |
|---|---|
| PC 1920×1080、ノート 1366×768、Steam Deck 1280×800 | 収まる |
| iPad Air 横 1180×820 | 左が 13 切れる（取扱説明書 §4.2） |
| iPad 横 1080×810 | 左が 63 切れる |
| iPad 縦 810×1080 | 左が 198 切れる |
| スマートフォン 横 844×390 | 左が 181 切れ、下も 306 はみ出す |
| スマートフォン 縦 390×844 | 左が 408 切れる |

（数は画面の点の数。）

## 判断の仕方

評価軸は設計方針 §1 の優先順位。

1. ルールの正しさ：練習に要るもの（札・盤面・入力・判定・操作）が、対応する大きさのどれでも欠けずに見えること
2. 変更容易性：画面の作りが、大きさごとにばらばらにならないこと。札面の差し替え（段階 5）に耐えること
3. テスト容易性：対応する大きさで、収まることを機械的に確かめられること
4. 移植性：公開先（PC、タブレット、Steam Deck）を、同じ画面のコードで扱えること
5. 性能：基準の端末で、起動時間の予算を守ること

## 論点と決定

### 1. 画面の大きさへの合わせ方

| 選択肢 | 中身 |
|---|---|
| A | 決まった大きさで描く（サンプル） |
| B | 画面の大きさの区分を細かく分け、区分ごとに別の配置を作る |
| **C** | **盤面と札は、縦横の比を保ったまま、使える領域いっぱいに拡大・縮小する。画面全体の配置は「横長」と「縦長」の2つだけを作る** |

**トレードオフ**：大きさごとの作り込み、に対して、作る配置とテストの数。

**決定：C。**

- A は、画面が小さいと盤面が切れる（取扱説明書 §4.2）。
- B は、区分の数だけ配置とテスト（見た目の比較を含む）が増え、区分の境目で崩れやすい。
- C なら、盤面がはみ出すことは、作りの上で起きない。配置は2つだけなので、テストも2つの形で済む。
  - 横長：盤面（または札）と、一覧などの補助の領域を、横に並べる。
  - 縦長：上下に積む。
- 札面は、拡大・縮小に耐える形で作る（段階 5 の札面の差し替えで、文字とフォントで組むか画像にするかを決めるときの条件にする）。

### 2. 小さい画面で、何を優先するか

**決定：練習の中心の領域は、対応する大きさのどれでも、スクロールせずに1画面に収める。** 中心の領域とは、札または盤面、入力欄、判定、操作のボタン。

- 決まり字一覧などの補助の情報は、開閉できる領域に置き、場所が足りないときは閉じておく（サンプルの「決まり字一覧を表示」と同じ形）。
- 優先の順は、ADR-0006 の目的の順（答える → 結果を知る → 進み具合を知る → 次の操作を知る）。
- 設定画面は、項目が多いので、縦にスクロールしてよい。

### 3. 操作の対象の大きさ

**決定**：

- ボタンなどのタッチで押す対象は、どれも 44×44 以上にする（Apple のガイドラインの最小の大きさ）。
- 盤面の札は、それ自体がタッチで押す対象になる。札の幅には下限を設ける（仮に 55。札面の文字が読める大きさ）。下限は、段階 5 で札面を決めたときに見直す。
- キーボードとコントローラーで操作するときは、今どの対象にいるかが、見て分かるようにする（ADR-0006 論点 5）。

### 4. 対応する機器と画面の大きさ 【要確認】§9 の 1

盤面は 11 列あるので、札の幅の下限（論点 3）を守るには、盤面に横 640 ほど、縦 500 ほどが要る。スマートフォンの画面には入らない（横向きでも、縦が足りない）。

| 選択肢 | 中身 |
|---|---|
| A | PC とタブレットだけに対応する。スマートフォンには対応しない |
| **B** | **PC とタブレットでは、すべての画面に対応する。スマートフォンでは、盤面を使わない画面（札流し、複数枚、設定、トップなど）に対応し、盤面を使う画面（配置暗記、実践練習）では、大きい画面で使うよう案内する** |
| C | スマートフォンでも、盤面を縮めてすべての画面に対応する |

**提案：B。**

- C は、スマートフォンの縦の画面で札の幅が 33 ほどになり、札面の文字が読めない。練習として成り立たない。
- B なら、札流しと複数枚（札1枚〜6枚を見て答える練習）は、スマートフォンでも十分に使える。盤面を使う練習だけを、大きい画面に限る。
- A より B の方が、増える手間は少ない。論点 1 の「縦長」の配置で、札流しと複数枚はスマートフォンの縦の画面にもそのまま収まる。増えるのは、盤面を使う画面での案内だけ。

盤面を使う画面に対応する大きさは、盤面が札の幅の下限を守って収まること、で決める。目安は、短い辺が 600 以上、長い辺が 900 以上（PC、Steam Deck、タブレット）。

### 5. 向き

**決定：画面の向きは固定しない。** 横長と縦長のどちらでも、論点 1 の2つの配置のどちらかで表示する。

- タブレットは、横でも縦でも使える。
- スマートフォンで盤面を使う画面を開いたときは、論点 4 の案内を出す。

### 6. 基準の端末 【要確認】§9 の 2

**決定：公開先ごとに、基準の端末を1台決め、起動時間の予算（ADR-0001）と、画面の収まり（論点 2）を、その端末で確かめる。** 基準は、その公開先で、手元にある端末のうち最も遅いもの。

| 公開先 | 基準の端末の候補 |
|---|---|
| Web | CI（今のとおり）。加えて、Chromium で CPU を 4 倍遅くした状態でも、起動時間の予算に収まることを CI で確かめる |
| iPad（iOS/iPadOS） | 手元の iPad のうち最も古いもの |
| Android | 手元の Android 端末のうち最も古いもの |
| PC・Steam | Steam Deck（手元にあれば）。対応する PC のうち、性能が低い側の代表になる |

- 具体的な機種は、手元の端末を伺ってから決める（§9 の 2）。
- CPU を遅くした状態の確認は、遅い端末の代わりにはならないが、遅くなる変更を CI でその場で止められる。

### 7. テスト

**決定**：

- E2E の画面の大きさに、次を足す。いま足りないのは、§4.2 で切れていた iPad の横の大きさと、Steam Deck の大きさ。

| 名前 | 大きさ | エンジン | 走らせるテスト |
|---|---|---|---|
| デスクトップ（今のとおり） | 1280×720 | Chromium・Firefox・WebKit | すべて |
| iPad 縦（今のとおり） | 810×1080 | WebKit | すべて |
| iPad 横 | 1180×820 | WebKit | すべて |
| Steam Deck | 1280×800 | Chromium | 収まりの確認と、コントローラー操作の確認 |
| スマートフォン縦 | 390×844 | WebKit | 収まりの確認と、対応する画面のテスト（論点 4 で B にした場合） |

- 各画面について、「練習の中心の領域が、画面からはみ出さない」ことを、それぞれの大きさで確かめる（論点 2）。
- 見た目の比較（スクリーンショット）は、横長と縦長の2つの配置について、段階 5 で基準の画像を作る。

## この ADR で決めないこと

| 事項 | 決める所 |
|---|---|
| 各画面の配置の細部 | 各画面の仕様（段階 4） |
| 札面の作り方（文字とフォントか、画像か） | 段階 5。拡大・縮小に耐えることを条件にする（論点 1） |
| 札の幅の下限の値 | 段階 5 で札面を決めたときに見直す（今は仮に 55） |
| 包み方（Tauri か Electron など） | その公開先に出すと決めたとき（ADR-0001） |

## 却下した選択肢

| 選択肢 | 退けた理由 |
|---|---|
| 決まった大きさで描く | 画面が小さいと、盤面が切れる（取扱説明書 §4.2） |
| 画面の大きさの区分を細かく分ける | 配置とテストが区分の数だけ増え、境目で崩れやすい |
| スマートフォンでも盤面を縮めて出す | 札面の文字が読めず、練習にならない |
| 画面の向きを固定する | タブレットは、横でも縦でも使われる |

## 範囲と制約

### 標準でできること

- PC、Steam Deck、タブレット（横・縦）で、すべての画面を、盤面が切れずに使える。
- 盤面がはみ出さないことを、対応する大きさごとに自動で確かめられる。

### 追加実装でできること（実施するかは別途判断）

- スマートフォンで盤面を使う練習（盤面の一部を拡大して見る、など、別の見せ方を考える必要がある）。

### 諦めること

- スマートフォンで、配置暗記と実践練習をすること（論点 4 を B にした場合）。

## この決定を見直す条件

- 札面を決めたとき（段階 5）。札の幅の下限と、対応する大きさを見直す。
- スマートフォンで盤面を使う練習の求めが出たとき。
- 手元の基準の端末が変わったとき。

## 9. 確認してほしいこと

1. **スマートフォンへの対応**（論点 4）。提案は B（スマートフォンでは、盤面を使う画面だけを、大きい画面で使うよう案内する）。
2. **基準の端末**（論点 6）。手元にある端末（iPad の機種、Android の端末、Steam Deck の有無）を教えてほしい。それぞれの公開先の基準の端末にする。
