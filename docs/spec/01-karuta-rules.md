# 仕様 01: 競技かるたの前提と決まり字

この文書は、すべての練習モードが前提とする競技かるたのルールと用語（ユビキタス言語）を定める。
特に **決まり字** と **決まり字変化** を厳密に定義する。各練習モードの仕様（札流し・決まり字変化札流し・実践練習）は、この文書の定義の上に書く。

## 1. 競技の流れ（前提知識）

1. 百人一首の取り札100枚をよく混ぜ、2人がそれぞれ25枚を無作為に取る（**持ち札**）。残りの50枚は使わない（**空札**）。
2. 持ち札を自陣に3段で並べる。2人の陣が向かい合うので、場全体は6段になる。
3. 暗記時間の後、読手が **序歌**（百人一首に含まれない歌）を読み、続けて1首目を読む。以降は「前の歌の下の句 → 次の歌の上の句」の順で読む。
4. 読まれた歌の取り札（**出札**）に先に触れた方が取る。相手陣の札を取ったら、自陣の札を1枚相手に送る（**送り札**）。
5. 出札がない陣の札に触れると **お手つき** となり、相手から札を1枚送られる。空札が読まれたときに札に触れた場合もお手つき。
6. 先に自陣の札がなくなった方が勝ち。

重要な点として、**読手は空札も読む**。場に取り札がない歌も読まれるため、選手は「どの歌がもう読まれたか」を覚えておく必要がある。

## 3. かなの表記

決まり字は、競技かるたの決まり字表で一般的に使われる表記（現代仮名遣いのひらがな）で書く。

- 歴史的仮名遣いは現代仮名遣いに直す。
  - 例：「をぐらやま」（26番）→「おぐらやま」
  - 例：「ゆふされば」（71番）→「ゆうされば」
- 助詞の「は」「を」は、発音ではなく表記どおりに書く。
  - 例：63番「いまは」（発音は「いまわ」）、48番「かぜを」（発音は「かぜお」）、62番「よを」（発音は「よお」）
- ローマ字は、発音ではなくかな表記を写したものとする。
  - 例：いまは = imaha、かぜを = kazewo、よを = yowo
  - 入力として受け付ける揺れ（fu / hu など）は [仕様 02](02-answer-input.md) で定める
- 濁音・半濁音は区別する（例：5番「おく」と 26番「おぐ」は別の決まり字）。
- 1文字は、かな1文字（Unicode のコードポイント1つ）として数える。
- **例外：44番（あふことの）は「おおこ」と書く。** 現代仮名遣いでは「おうこ」だが、音が「おお」と同じため、60番「おおえ」・95番「おおけ」と組になって3字決まりになる。「おうこ」と書くと文字の比較で2字決まりになってしまい、決まり字表の分布（§4.2）と合わない。現行サンプルのデータも「おおこ」。
- 決まり字に現れる文字は次のとおり（拗音・促音・撥音は現れない）：
  `あいうえおかがきぎくぐけげこごさざしじすせぜそたちつとなにぬのはひびふほぼまみむめもやゆよらりるれろわを`

表記の正は、静的決まり字のマスターデータ（100首分）に置く。決まり字の計算は、すべて静的決まり字を基準にする（§4）。歌の全文（読み）は、データとして持たない。決まり字グループ（§7）も、確かめ済みの固定のデータとしてマスターデータに含める。どちらも実行時には計算しない。データの食い違いは、テストで見つける（§8.3）。

## 4. 決まり字の定義

### 4.1 定義

決まり字の意味：上の句をその文字まで聞いた時点で、候補の中でどの歌か確定する、最短の文字列。

計算は、静的決まり字（§4.2）を基準にして行う。

- 候補集合を C、C に含まれる歌を p、p の静的決まり字を s(p) とする。
- 2つの文字列の先頭から一致する文字数を LCP（最長共通接頭辞の長さ）と書く。
- p の決まり字の長さ k(p, C) は次のとおり。

```
k(p, C) = min( |s(p)|,  max{ LCP(s(p), s(q)) | q ∈ C, q ≠ p } + 1 )
```

- C に p 以外の歌がない場合、max は 0 とみなす（k = 1）。
- 決まり字 kimariji(p, C) は、s(p) の先頭 k(p, C) 文字。
- C が100首全体のとき、kimariji(p, C) は s(p) そのものになる。

この式が、決まり字の意味（上の句を聞いて確定する）と一致する理由は §4.3。

決まり字は最短でも1文字で、0文字（読まれる前に確定）にはならない。候補が1首だけになっても同じである。現行サンプルも、札流し・実践練習ともに最小1文字で計算している。

### 4.2 静的決まり字

候補集合が100首全体のときの決まり字。決まり字の計算の基準となるデータで、マスターデータとして持つ（§8.3）。分布は次のとおり（現行サンプルのデータで確認済み）。

| 文字数 | 1 | 2 | 3 | 4 | 5 | 6 | 計 |
|---|---|---|---|---|---|---|---|
| 首数 | 7 | 42 | 37 | 6 | 2 | 6 | 100 |

1字決まりの7首は「むすめふさほせ」。

### 4.3 静的決まり字を基準にしてよい理由

実戦では、決まり字は上の句の全文を先頭から聞いて決まる。それでも静的決まり字を基準にしてよいのは、異なる2首 p, q について、全文どうしの LCP と、静的決まり字どうしの LCP が必ず一致するからである。

理由：全文どうしの LCP を L とする。静的決まり字の定義より、p の静的決まり字も q の静的決まり字も L 文字より長い。どちらも全文の先頭部分なので、先頭の L 文字は一致し、L+1 文字目は全文と同じく異なる。したがって、静的決まり字どうしの LCP も L になる。

このため、どの候補集合でも、§4.1 の式は全文で計算した場合と同じ決まり字を返す。歌の全文をデータとして持つ必要はない。

## 5. 決まり字変化

### 5.1 規則

歌 x が読まれたら、候補集合から x を取り除く。

```
C(t+1) = C(t) \ { x(t) }
```

残った歌の決まり字は、新しい候補集合で §4.1 の式により計算し直す。

- **出札か空札かを問わず**、読まれた歌は候補から外れる。
- 場に取り札が出ているかどうかは決まり字に **影響しない**。空札も読まれうるので、未読の空札は候補に残る。

### 5.2 例（現行データで検証済み）

| 既読になった歌 | 対象の歌 | 変化前 | 変化後 |
|---|---|---|---|
| うら（65番） | うか（74番） | うか | う |
| つき（23番） | つく（13番） | つく | つ |
| ちぎりき（42番） | ちぎりお（75番） | ちぎりお | ちぎ |
| あさぼらけう（64番） | あさぼらけあ（31番） | あさぼらけあ | あさぼ |
| あさぼらけう（64番）、あさじ（39番） | あさぼらけあ（31番） | あさぼらけあ | あさ |
| きみがためは（15番） | きみがためお（50番） | きみがためお | きみ |

最後の例のように、6字決まりが一気に2字決まりになることもある。

## 6. 候補集合の決め方

### 6.1 原則

練習の設定（出題対象の絞り込み、出題枚数、空札を読むかどうかなど）が変えるのは、**どの歌を・どの順で・どの速さで出題するか** だけとする。**何が正解か（決まり字）は変えない。** 正解は常に、実戦で同じ状況になったときの正解と一致させる。

理由：実戦で正しくない判断を練習で「正解」にすると、誤った癖が身につく。例えば「うか」だけを選んだ練習で「う」を正解にすると、実戦で「うら」が読まれたときにお手つきをする癖がつく。

### 6.2 候補集合

候補集合は、公式戦でもすべての練習モードでも **100首 − 既読** とする。

- **既読**：このセッションで実際に出題した（読んだ）歌。出題対象を限定しているかどうか、空札かどうか、場に取り札があるかどうかは関係ない。
- 出題されないまま終わった歌は、最後まで候補に残る。実戦でも、まだ読まれていない歌は読まれうるからである。
- 決まり字変化を扱わない練習（通常の札流し）では、候補集合を常に100首とする。つまり正解は静的決まり字になる。

### 6.3 例：出題対象を絞り込んだ場合

「は」で始まる4首を選んで決まり字変化を練習した場合（「は」で始まる歌は100首中この4首だけ）：

| 既読 | はなさ | はなの | はるす | はるの |
|---|---|---|---|---|
| なし | はなさ | はなの | はるす | はるの |
| はなさ | — | はな | はるす | はるの |
| はなさ、はるす | — | はな | — | はる |
| はなさ、はるす、はるの | — | は | — | — |

グループの一部（「はなさ」「はるす」）だけを選んだ場合。選んでいない「はなの」「はるの」はまだ読まれうるので、候補に残る：

| 既読 | はなさ | はるす |
|---|---|---|
| なし | はなさ | はるす |
| はなさ | — | はるす |

比較のため、絞り込んだ歌だけを候補にした場合（現行サンプルの札流しの挙動。本仕様では採用しない）を示す。正解は「はな」「はる」、次に「は」となる。実戦なら「はるす」まで聞かないと取れない場面で、「は」で取る練習をしてしまう。

## 7. 決まり字グループ

設定画面で「あ」「あさ」のように歌をまとめて選ぶための単位。現行サンプルでは46グループを手入力していた。

決まり字グループは、確かめ済みの固定のデータ（46グループ）として持つ。実行時には計算しない。

定義（データの意味。§8.3 の食い違いのテストにも使う）：静的決まり字の、末尾を除く先頭部分（接頭辞）を共有する歌が2首以上ある場合に、その歌の集合を1グループとする。同じ歌の集合になる接頭辞が複数ある場合は、最も短いものをグループ名にする。

- 例：「あさぼ」「あさぼら」「あさぼらけ」はどれも {31番, 64番} になるので、グループ名は「あさぼ」。
- この定義で求めたグループは、現行サンプルの46グループと完全に一致する（確認済み）。
- 現行サンプルではグループ ID 129 が「ちぎ」と「ひと」で重複していた。新しい版では、グループを名前（例：「あさぼ」）で識別し、番号を手で振らない。名前が重複していないことと、データが定義どおりであることは、テストで確かめる。

## 8. テストへの落とし込み

### 8.1 テストベクタ（言語非依存の JSON）

仕様の具体例は、すべてテストベクタとして持つ。将来ほかの言語に移植するときも、同じデータで検証する。

```json
{
  "id": "kimariji-change/ura-read-uka-becomes-u",
  "description": "「うら」が読まれると「うか」は一字決まりになる",
  "read": [65],
  "poem": 74,
  "expectedKimariji": "う"
}
```

用意するベクタ：

- §4.2 の分布
- §5.2 の決まり字変化の例
- §6.3 の候補集合の例

静的決まり字と決まり字グループは、マスターデータそのものとして持つ（§8.3）。

### 8.2 性質（プロパティベーステスト）

任意の候補集合 C と、C に含まれる歌 p について：

| ID | 性質 |
|---|---|
| P1 一意性 | C に含まれる p 以外のどの歌 q についても、kimariji(p, C) は s(q) の先頭部分にならない |
| P2 最短性 | 決まり字が2文字以上なら、1文字短い文字列は、C に含まれる p 以外のある歌の静的決まり字の先頭部分になる |
| P3 単調性 | C' ⊆ C ならば、k(p, C') ≤ k(p, C)。候補が減って決まり字が長くなることはない |
| P4 1首だけ | C = {p} ならば k(p, C) = 1 |

### 8.3 マスターデータと、食い違いのテスト

マスターデータは、歌番号・静的決まり字・決まり字グループの3つ。どれも確かめ済みの固定のデータで、実行時には計算しない。歌の全文は持たない（§3）。

作るときの確認：現行サンプルのデータを元にする（決まり字グループは ID 129 の重複を直したもの）。静的決まり字は、§4.2 の分布と一致することを確かめる。

テストで確かめること。データの正しさを毎回疑うためではなく、データを新しい形に写すときの写し間違いと、後で誤って編集したことを見つけるため：

- 歌番号は 1〜100 がちょうど1回ずつ現れる
- 静的決まり字は §3 の文字だけで構成される
- 一意性：どの歌の静的決まり字も、ほかの歌の静的決まり字の先頭部分になっていない
- 最短性：2文字以上の静的決まり字は、最後の1文字を除いた部分が、ほかのある歌の静的決まり字の先頭部分になっている
- 静的決まり字の分布が §4.2 と一致する（§8.1 のベクタ）
- 決まり字グループは、静的決まり字に対して §7 の定義を満たし、名前が重複していない

一意性と最短性の2つは、「候補集合を100首にして §4.1 の式で計算すると、静的決まり字そのものに戻る」ことと同じである。

## 9. 現行サンプルとの対応

現行サンプル（タグ `sample`）を実際に動かし、コードも確認した結果を記す。候補集合の決め方がモードごとに異なり、統一されていない。

| モード | 現行サンプルの候補集合 | 確認方法 |
|---|---|---|
| 札流し | 限定 ON：選んだ歌 − 回答済み。限定 OFF：100首 − 回答済み。出題枚数の上限で出題しなかった歌は候補に残る | 実行して確認。「はなさ」「はるす」だけを選ぶと最初の正解が「はな」、「うか」だけを選ぶと「う」になる |
| 札流し（複数枚） | 2枚以上の問は常に静的決まり字（前の問も考慮しない）。最後の問が1枚だけのときは、その1枚だけで計算するため常に1文字 | 実行して確認 |
| 実践練習 | 限定 ON：選んだ歌、OFF：100首。「空札を除外」ON ならそのうち場にある歌だけ。そこから出題済みを除く | コードで確認 |

そのほかの差分：

| 項目 | 現行サンプル | 新設計 |
|---|---|---|
| 決まり字の計算 | 静的決まり字どうしの LCP で計算 | 同じ計算（§4.3 で正しさを保証） |
| 静的決まり字 | 手入力 | 決まり字の計算の基準となるマスターデータとして持つ。サンプルのデータを元にし、分布と一意性・最短性をテストで確かめる（§8.3） |
| 決まり字グループ | 手入力（ID 129 が重複） | 重複を直した固定のデータとして持ち、名前で識別する。静的決まり字との食い違いをテストで見つける（§7、§8.3） |
| 札流しの「決まり字変化を考慮する」設定 | 読み込まれるが使われていない。OFF にしても決まり字変化した答えが正解になる（実行して確認） | 通常の札流しと決まり字変化札流しを別のモードにする（§6.2） |
| 候補集合 | モードごとにばらばら | 全モードで §6.2 に統一 |
