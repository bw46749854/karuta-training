## 1. 設定画面と、入口のトップ画面（[仕様 04](../spec/04-settings-and-top.md)）

### 1.1 置いたもの

| ファイル | 中身 |

| `settings/definition.ts` | 全項目の定義（仕様 04 §5）。初期値は取扱説明書の「設定画面の初期値」（仮） |

### 1.2 テストを先に書いて、失敗を確かめた

- 受け入れテスト：画面を作る前に動かし、新しい 8 件と axe の 2 件、計 10 件が失敗した（ボタンや見出しが見つからない。トップ画面の axe は、空の `main` が見えないため待ちきれずに失敗）。起動時間の 1 件は通った。
- `application`：新しいテストと、全項目に合わせて直したテストを先に書き、19 件が失敗した（部品と操作がまだないため。入力欄の一覧のテストのファイルは、読み込みの時点で失敗）。
- 設定画面のコンポーネントテスト（3 件）：画面より先に書いたが、失敗を見ずに画面を書いた。後から、整数の入力欄を出さない版と、メッセージを消さない版に壊して動かし、2 件が失敗することを確かめた。保存の失敗を知らせるテストは、この壊し方では失敗しなかった（壊していない所を確かめるテストのため）。

## 2. 札流し（[仕様 05](../spec/05-card-flow.md)）

### 2.1 置いたもの

| ファイル | 中身 |
|---|---|
| `packages/application/src/card-flow/card-flow.ts` | 札流しのモード（ADR-0004）。段階は出題中・判定後・終わりで、出題中と判定後は今の問を持つ。決まり字一覧の行と並び。設定と乱数から1回分の出題を作る（`cardFlowInput`） |
| `packages/ui/src/card-flow-screen.tsx` ほか | 札流しの画面、札（仮の札面）、決まり字一覧 |
| `apps/web/e2e/card-flow.spec.ts` | 受け入れテスト 13 件。ページを読み込む前に `Math.random` を 0 を返すものに替え、出る順を決める（ADR-0002 §5） |

### 2.2 テストを先に書いて、失敗を確かめた

- 受け入れテスト：画面を作る前に動かし、10 件すべてが失敗した（トップ画面に「札流し」がない）。
- `application`：中身のない仮のモードで動かし、15 件すべてが失敗した。中身を書いた後、1 件だけ失敗が残った。テストの期待値の誤りだった（乱数が常に 0 のとき、2首のシャッフルは入れ替わる）。コードではなくテストを直した。
- 画面ができた後に、再現手順書の「直したら確かめること」を見直し、受け入れテストを 3 件足した（B-26 の一度も保存していないとき、B-17 の限定 OFF、B-21 の対象が出題枚数より少ないとき）。作った後の動きを確かめるテストなので、初めから通った。
- `ui` の部品（決まり字一覧、札）：コンポーネントテストは、画面を書いた後に書いた。一覧を初めから開いた版と、逆さまの印を付けない版に壊して動かし、2 件とも失敗することを確かめた。

### 2.3 検証で見つかったこと

- 画面を足した後の `pnpm verify` で、分岐のカバレッジが 94.47% になり、閾値の 95% を下回って止まった。原因は、起こりえない場合のための分岐（今の問がないとき、文言の型が違うとき、など）。
- 今の問を段階の中に持たせ、入力欄の一覧は検証済みの値をそのまま読む形に直して、起こりえない分岐をなくした。分岐のカバレッジは 100%（193/193）になった。

## 3. 画面の大きさ（ADR-0007 §7・§10）

- 日付：2026-11-05

`apps/web/e2e/screen-sizes.spec.ts` を足した。ADR-0007 §10 の 6 つの大きさ（デスクトップ 1280×720、iPad 横 1180×820、iPad 縦 810×1080、Steam Deck 1280×800、スマートフォン横 844×390、スマートフォン縦 390×844）で、次を確かめる。

- 札流し：札・入力欄・「答える」・「スキップ」・判定が、スクロールせずに1画面に収まる。
- 設定画面：横にはみ出さない（縦のスクロールはよい）。

大きさは、プロジェクトの画面の大きさを上書きして作る。どのプロジェクト（エンジン）でも、6 つの大きさをすべて確かめる。ADR-0007 §10 の「大きさごとのプロジェクト（エンジンを決めたもの）」は、まだ足していない（[報告](stage-4-review.md) §4）。

すでにある画面の確かめなので、テストは初めから通った。本当に失敗できることは、壊した版で確かめた。

- 札の高さを 400 にした版：スマートフォン横の札流しが失敗した。
- 札の配置の枠の横スクロールを外した版：スマートフォン縦の設定画面が失敗した。

気づいたこと：スマートフォン縦（390）では、6段×11列の札の配置の編集（1マス 44 の11列）が枠の中で横にスクロールする。ページははみ出さない。
